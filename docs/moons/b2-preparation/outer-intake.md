## Charon: selected PDS MVIC color mosaic

The current package has a 12,693 × 6,347 USGS 2017 monochrome mosaic and DEM on a 300 m grid; the 452-face reference sphere remains undisplaced. The new source is [nh_charon_color_mosaic.img](https://pds-smallbodies.astro.umd.edu/holdings/pds4-nh_derived-v4.0/plutosystem_composition/mosaic/nh_charon_color_mosaic.img), with its [PDS4 label](https://pds-smallbodies.astro.umd.edu/holdings/pds4-nh_derived-v4.0/plutosystem_composition/mosaic/nh_charon_color_mosaic.lblx). LIDVID: `urn:nasa:pds:nh_derived:plutosystem_composition:nh_charon_color_mosaic::1.0`. The PDS4 label migrated the earlier PDS3 product on 2025-05-04; the binary has archive Last-Modified 2018-06-26. This is an additional color observation, not a new terrain model.

Acquired body-owned input: `src/planets/charon/source/observations/nh_charon_color_mosaic.img`, **116,006,912 bytes**, SHA-256 `dd23352035996d670b9c278a1466461623556acc88d66aabd3bc2da1dd15fc5a`. Full download receipt is beside the binary in `nh-charon-color-download.json`. The label and the collection overview PDF are retained beside it. Acquisition recipe and manifest registration are pending implementation.

The label explicitly targets Charon and declares 4 bands × 1,904 lines × 3,808 samples, last-index-fastest, band-sequential IEEE754 little-endian float32, zero byte offset. Band centers/widths are CH4 895/40 nm, NIR 870/180 nm, red 625/150 nm, blue 475/150 nm. Selected display RGB is one-based bands **2, 3, 4** (NIR, red, blue), with one common linear display range initially proposed as 0–0.6. That range is a display choice, not a measurement calibration or three independent channel stretches.

Coordinates are equirectangular, planetocentric, east-positive, central meridian 0°, standard parallel 0°, reference sphere 606,000 m, upper-left corner (−1,904,000, 952,000) m, and 1,000 m pixels. Pixel centers use `x = originX + (sample + 0.5) × 1000`, `y = originY − (line + 0.5) × 1000`; longitude and latitude are x/R and y/R in radians. Grid extents are rounded and therefore not exactly 360° × 180°. The old 300 m product has a different origin, (−1,903,950, 952,200) m. The decoder must project geographically, not align these arrays by index or stretch the rounded extent into 2:1 longitude coordinates.

Missing data is the **finite** float bit pattern `0xFF7FFFFB` (about −3.4028226551e38). Before interpolation, reject that exact code and any nonfinite value across all three selected bands and the complete bilinear footprint. Valid negative values are not automatically missing. Independent NumPy decoding found band-valid counts 4,105,716 / 4,105,747 / 4,105,766 / 4,105,746. Their selected RGB intersection contains 4,105,311 of 7,250,432 source pixels (approximately **60.0019% surface area** after cosine latitude weighting). This is source-center coverage, before the conservative interpolation mask. No color is inferred for the remaining area.

Independent raw-byte anchors are retained in `src/planets/charon/source/validation/color-source-inspection.json`: (0°E, 0°N) nearest sample/line (1904,952) has RGB 0.4117498696 / 0.4493312240 / 0.4719758928; (0°E,80°N) at (1904,105) has 0.2344332486 / 0.1650196165 / 0.1310233623. The northern NIR/red/blue relation agrees with the mission's independently described reddish polar region. (180°E,0°N), (0°E,−50°N) and the south pole have the exact missing code. These checks come from a separate Python/NumPy decoder, not the proposed JavaScript decoder.

The [collection overview](https://pds-smallbodies.astro.umd.edu/holdings/pds4-nh_derived-v4.0/plutosystem_composition/overview.pdf) says the scans were registered to the LORRI basemap, normalized with a combined lunar-Lambert model near L=0.65 at 15° phase, then merged with panchromatic imagery. Thus 1 km grid spacing is not uniform native color resolution. The label warns that mosaicking means values are no longer strictly I/F. The proposed lens is **Enhanced color**, explicitly false color and pan-sharpened; it must not say natural color, measured albedo, or uniform-resolution spectroscopy. The binary blue band includes finite negative and high outliers; display clamping is explicit and does not turn these into missing coverage. The overview refers calibration uncertainties to Howett et al. (2017); no per-pixel uncertainty array accompanies this mosaic. Terrain south of approximately −38° was dark during the encounter, and the actual mask determines all displayed coverage.

Independent interpretation references: [NASA enhanced-color description](https://science.nasa.gov/resource/charon-in-enhanced-color/) and [New Horizons MVIC filter explanation](https://science.nasa.gov/blogs/new-horizons/2016/02/12/the-many-faces-of-pluto-and-charon/). Cite NASA/JHUAPL/SwRI, map author Paul Schenk/LPI, the exact archive LIDVID, and the collection authors. PDS data use is public scientific-data reuse with source citation; no specific Creative Commons license is invented for this product. Follow [PDS citation guidance](https://pds.nasa.gov/datastandards/citing/).

**Target guard:** the collection overview generically mentions absorption maps for Pluto and Charon, but the inspected `absorp/leisa_809-889-014_si-h2o_norm_i89.lblx` explicitly targets **Pluto**, and all four listed absorption maps have Pluto identities. Those maps are excluded from Charon. No Charon water or methane map is claimed from them.

Decoder proposal: new preparation-only `observed-pds4.mjs`, exports `validatePds4ObservationPolicy`, `readPds4ColorLabel`, `decodePds4Color`, `mapPds4Color`, and `preparePds4Observation(sourceDirectory, entry, policy, width, height)`. Policy uses `kind: pds4-float-rgb`, pinned `labelPath`, exact `lidvid`, one-based `bands: [2,3,4]`, `wavelengthsNm: [870,625,475]`, and `displayRange: [0,0.6]`. Return the existing `{rgb, missing, sourceMissingPixels, sourceGeoreference}` shape. Fail closed on unsupported axis order, scaling, byte layout, units, projection, selected wavelengths, file name or dimensions. Root owns shared dispatch/validation. Test missing finite float sentinels, channel selection, map orientation, rounded edges and pre-interpolation validity. Automatic approval review rejected two shared-module writes after applying the earlier intake-only boundary. No shared module was written by this lane. Root now owns review and application from its B2 implementation context. The proposal is `/tmp/observed-pds4.mjs`, its repo-relative-label test is `/tmp/observed-pds4.test.mjs`, and seven body changes are `/tmp/charon-b2-proposal/charon-body.patch`. `git apply --check` passed. All six tiny decoder tests passed; a separate actual-source run matched ten independently decoded anchors (40 band values) and checked a 360 × 180 projection at 298 MB RSS. See [decoder proof](charon-decoder-proof.json).

Budget: new source 110.63 MiB plus small metadata, currently acquired; no large bake started. A new 12,800 × 6,400 color layer can require multiple >300 MB temporary raster buffers, so any full preparation needs a fresh disk/memory-pressure preflight and root's serialized scheduling slot. No 16 GiB heap override. The small source inspection completed independently.

## Miranda: selected 2026 geologic map

Current package: Schenk/LPI 2020 monochrome and elevation at 6,294 × 3,147, 240 m grid; stereo/photoclinometry elevation is displayed on a 235.7 km reference sphere, not displaced geometry. Existing mosaic and DEM longitude origins differ (−180…180 and 0…360), already handled by their recipes. Reusing that DEM alone does not close B2.

Selected new product: Thomson, Bradley; Baynham, Devon (2026), [Digitized geologic map of the Uranian moon: Miranda](https://doi.org/10.5281/zenodo.20817533). Release issued June 23, 2026; metadata declares **CC BY 4.0**. Exact DOI-registry receipt: [miranda-geology-datacite.json](miranda-geology-datacite.json). The cached publisher record lists `Miranda map 1.gdb.zip` (224.9 kB), MD5 `db54def90f4c6b160e9935ed36986eee`, alongside ArcGIS project and layer-style files. Direct URL: `https://zenodo.org/records/20817533/files/Miranda%20map%201.gdb.zip?download=1`. This checksum is publisher-listed, not a local downloaded-byte proof.

Python public API/direct-file reads returned HTTP 403. System curl GETs with a descriptive project user agent and then a normal browser user agent each timed out after 30 s with no payload. Browser-tool entry was unavailable. A final public GET established the exact archive explanation: “Access to this resource has been restricted due to unusual traffic from your network.” The same response occurs for the Titania record and both file-list endpoints. Retries stopped. See [access receipt](gis-access-block.json). These failures do not imply the release lacks usable data. Do not claim GIS decoding, coordinates, coverage, field semantics, topology, or registration is qualified yet.

Implementation closure requires the actual GDB plus relevant layer-style metadata; enumerate native feature classes/geometry types, unit dictionary, projection WKT, units and longitude direction. Convert category polygons once in preparation with nearest-category sampling and preserve holes/unmapped terrain. Independently compare Elsinore (257.1°E,−24.8°), Arden (73.7°E,−29.1°), Inverness (325.7°E,−66.9°), the south pole and control meridians against the existing registered basemap; reserve disjoint landmarks to estimate registration error. A declared ArcGIS projection without alignment evidence is insufficient. Honor each unit's mapped footprint; interpreted geology is not a composition measurement or direct age raster.

Alternative checked: Leonard et al. (2023), [Unraveling the Geologic History of Miranda’s Inverness Corona](https://doi.org/10.3847/PSJ/ad0552), and its [NASA JPL archive](https://doi.org/10.48577/jpl.XNJIQV). The JPL API successfully lists **only** `CL23_6005.pdf` (7,915,242 bytes), no vector/DEM download. [Archive metadata receipt](miranda-jpl-archive.json) is retained; its general CC0 record license does not override the paper's own license. This is a paper route, not evidence of released GIS. Its regional topography references Beddingfield et al.'s actual 2022 heat-flux paper, [PSJ 3:174, DOI ac7be5](https://doi.org/10.3847/PSJ/ac7be5); the 3:106 citation seen in some conference references is not the verified article identity. The regional DEM is scientifically distinct, but no actual downloadable grid was qualified in this intake.

## Titania: newly identified 2026 geologic map

Current package: Schenk/LPI 2020 monochrome and DEM at 1,722 × 861, 2,880 m grid, east-positive planetocentric coordinates on a 788.9 km sphere. Current imagery covers about 44.8% of surface area and elevation about 27.7%; elevation is color/relief, not displaced geometry. Current source documents already note that the Nathan–Head–Huber 2024 deblurring procedure discards geospatial information and needs separate registration.

New concrete selection: Thomson, Bradley; Baynham, Devon (2026), [Digitized geologic map of the Uranian moon: Titania](https://doi.org/10.5281/zenodo.20819132), issued June 23, 2026, **CC BY 4.0**. Exact metadata receipt: [titania-geology-datacite.json](titania-geology-datacite.json). It is a version of DOI `10.5281/zenodo.20089664`; earlier registered versions include `20089665` and `20598631`. DOI metadata describes ArcGIS Pro digitization of Voyager-era paper geology in the same Uranian-moon foundations project as Miranda. This release was found through an exact title field in the DOI registry after ordinary text searches missed it.

No actual file inventory or polygon coordinates have yet been retrieved. Therefore byte count, archive checksum, category dictionary, WKT, coordinate conventions, precision and observed footprint remain unresolved. Current priority is source-file closure for this exact release, then the same independent registration/coverage checks as Miranda. Useful disjoint anchors are Ursula, Gertrude, Messina Chasmata, Bona, the zero meridian and observed northern/southern limits. Do not represent source-paper page pixels as registered categorical measurements.

Other sources examined: Nathan, Head & Huber (2024), [Cratering and Tectonic History of the Largest Uranian Satellite, Titania](https://doi.org/10.3847/PSJ/ad04d6), and Beddingfield et al. (2023), [Titania’s Heat Fluxes Revealed by Messina Chasmata](https://doi.org/10.3847/PSJ/ad0367). The latter reports a new regional stereo/photoclinometry DEM projected about −16° latitude, 326° longitude, using Voyager ISS frames including c2684313 (2.88 km/pixel). It is distinct from the existing global DEM but no actual released grid was located. Its modeled historical heat flux is not a present-day surface temperature map. Neither paper has been counted as a drop-in image/vector source.
